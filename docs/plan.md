## 二、开发纪律

以下两条是全项目不可违反的硬约束，适用于每一个步骤文件中的每一项功能。

**第一条：绝对不能用空对象、空文件代替实现。**

不允许出现的做法：接口直接返回空对象或空数组充当结果；Service 方法体为空直接返回 null；Controller 存在但没有业务逻辑；页面只有外壳骨架、表格无数据源、按钮无处理函数；数据库表建了但没有任何读写路径。

**第二条：绝对不能把 TODO 当作实现。**

不允许在代码里留 TODO、FIXME、未实现标记、`throw new UnsupportedOperationException()` 来充当已完成的功能。某功能确实做不完，就在该步骤文件的进度栏如实写「未开始」或「进行中」，并写明卡在哪里，不得用占位代码充数。

**进度栏「已完成」的判定标准**：该行对应的交付物（接口、页面、数据表）全部存在，接口能返回真实业务数据，页面能真实读写，且不存在上述两条禁止的做法。达不到就是「进行中」，不准标「已完成」。

## 五、命名约定

### 5.1 接口路径

接口路径以业务模块为第一段，与论文的五个模块对应。

| 模块 | 路径前缀 | 权限串前缀 |
| --- | --- | --- |
| 模块一 基础数据与权限管理 | `/basic/**` | `basic:` |
| 模块二 故障报修与跟踪 | `/repair/**` | `repair:` |
| 模块三 工单调度与执行 | `/order/**` | `order:` |
| 模块四 预防性维保 | `/maintain/**` | `maintain:` |
| 模块五 数据分析与预警 | `/analysis/**` | `analysis:` |

### 5.2 权限串

三段式 `<模块>:<实体>:<动作>`。查询用 `:list`，增删改统一用 `:edit`，专有动作单独命名（如 `:dispatch`、`:accept`、`:archive`、`:export`）。

管理端页面按钮通过 `v-hasPermi="['basic:user:edit']"` 控制，后端接口通过 `@PreAuthorize("@ss.hasPermi('basic:user:edit')")` 控制。

### 5.3 前端文件

一个功能对应三处落点：

- 接口封装：`admin-web/src/api/<模块>/<实体>.js`
- 页面：`admin-web/src/views/<模块>/<实体>/index.vue`
- 菜单：`sql/data.sql` 中 `sys_menu` 表的一行

管理端路由由后端菜单树驱动，不在 `router/index.js` 中硬编码业务路由。
