# 步骤 03 — 后端基础框架

## 一、功能

### ruoyi-elevator 模块骨架
- 建立 Maven 子模块 `ruoyi-elevator`，依赖 `ruoyi-common` 与 `ruoyi-framework`
- 在 `ruoyi-admin` 中引入该模块，使 Spring 容器可扫描到电梯业务组件
- 建立包结构 `com.ruoyi.elevator`，下分 `controller`、`domain`、`mapper`、`service`
- `domain` 下按实体、入参、出参三类分：`domain`（实体）、`domain.vo`（出参）、`domain.dto`（入参）
- 配置 MyBatis 的 `mapperLocations` 扫描 `classpath*:mapper/elevator/**/*.xml`
- 新建一个连通性验证接口，读取数据库中电梯表的数据条数并返回，确认模块、Mapper、数据源三层打通

**交付物**

| 类型 | 清单 |
| --- | --- |
| Maven 模块 | backend/ruoyi-elevator/pom.xml |
| 包结构 | backend/ruoyi-elevator/src/main/java/com/ruoyi/elevator/ |
| Mapper 配置 | backend/ruoyi-admin/src/main/resources/application.yml 的 mapperLocations |
| 验证接口 | GET /elevator/ping 返回 elevator 表记录条数 |

### 统一响应与异常处理
- 沿用 RuoYi 的 `AjaxResult` 作为统一响应体，不另造包装类
- 沿用 RuoYi 的 `TableDataInfo` 作为分页响应体
- 沿用 RuoYi 的 `BaseController`，控制器继承它使用 `startPage()`、`getDataTable()`、`success()`、`error()`
- 建立业务异常类 `ElevatorException`，用于电梯业务的领域异常
- 建立全局异常处理器，捕获业务异常、参数校验异常、权限异常，统一返回可读的中文提示
- 建立自定义异常码枚举，覆盖工单状态非法、无权操作他人数据、维保计划重复等业务场景

### 权限与数据范围
- 沿用 RuoYi 的 `@PreAuthorize("@ss.hasPermi('xxx')")` 注解做接口级鉴权
- 建立当前登录用户工具类，从 Spring Security 上下文取用户 ID、用户名、昵称、角色、所属小区
- `LoginUserUtil.getCommunityId()` 读取 `sys_user.community_id`，管理员返回 null 表示不限制
- 数据范围在业务服务层落实：业主只能查询本人的报修工单，维修员只能查询指派给本人的工单，物业与维修员限定在所属小区内
- 该规则在各业务服务的 `applyDataScope` 中实现，模块二、模块三、模块五的查询接口共用

### 文件上传与存储
- 建立文件上传接口，接收图片与视频，限制格式与大小：图片单文件不超过 10MB，视频单文件不超过 50MB
- 上传成功后写入 `sys_file` 表，记录原文件名、存储路径、文件类型、文件大小、上传人
- 建立文件下载与预览接口，图片支持浏览器直接预览，视频支持在线播放
- 文件按业务类型分目录存储，业务类型含电梯证件、报修证据、巡检结果、导出报表
- 该能力被模块一的电梯证件上传、模块二的多媒体证据上传、模块四的巡检结果上传复用

- 配置任务执行日志落库，便于排查是否按时执行
