# 步骤 02 — 数据库设计与建表

## 一、功能

### 数据库与框架表准备
- 创建数据库 `elevator`，字符集 `utf8mb4`，排序规则 `utf8mb4_general_ci`
- 建立 RuoYi 框架表：`sys_user`、`sys_role`、`sys_menu`、`sys_role_menu`、`sys_user_role`、`sys_dict_type`、`sys_dict_data`、`sys_config`、`sys_job` 等，共 14 张
- 按论文 3.2.2 节剔除框架自带的部门表 `sys_dept`、岗位表 `sys_post`、角色部门关联 `sys_role_dept`、用户岗位关联 `sys_user_post`、代码生成器表 `gen_table` 与 `gen_table_column`
- `sys_user` 内置 `community_id` 字段关联所属小区，供数据权限按小区隔离使用
- 建库脚本合并为单一入口 `sql/elevator_init.sql`，内部按五章组织，可重复执行

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | sys_user、sys_role、sys_menu、sys_role_menu、sys_user_role 及 RuoYi 其余框架表，共 14 张 |
| SQL 脚本 | backend/sql/elevator_init.sql 第 2 章 |

### 模块一业务表建表
- 建立小区表 `community`：小区名称、地址、建成时间、物业联系人、联系电话
- 建立楼栋表 `building`：楼栋号、单元号、关联小区 ID
- 建立电梯表 `elevator`：电梯编号、品牌、型号、所在楼栋 ID、单元号、维保单位、投用日期、状态、使用年限
- 建立文件表 `sys_file`：统一存储电梯证件附件、报修证据、导出文件，记录原文件名、存储路径、文件类型、大小、关联业务类型与业务 ID
- 每张表含 `create_by`、`create_time`、`update_by`、`update_time`、`remark` 公共字段，每列写 `COMMENT`

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | community、building、elevator、sys_file |
| SQL 脚本 | backend/sql/elevator_init.sql 第 4 章第 1—4 节 |

### 模块二业务表建表
- 建立报修工单表 `repair_order`：工单编号、报修人 ID、故障电梯 ID、故障现象、故障等级、工单状态、报修时间、派单时间、接单时间、完成时间、确认时间
- 建立报修证据附件表 `repair_evidence`：关联工单 ID、文件 ID、文件类型（图片或视频）、上传时间
- 为工单状态、故障等级建字典项，字典类型为 `repair_order_status`、`fault_level`

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | repair_order、repair_evidence |
| 字典 | sys_dict_type 与 sys_dict_data 中的 repair_order_status、fault_level |
| SQL 脚本 | backend/sql/elevator_init.sql 第 4 章第 5—8 节、第 5 章第三节 |

### 模块三业务表建表
- 建立维修记录表 `repair_record`：关联工单 ID、维修员 ID、到场时间、排查记录、维修说明、更换配件、完工时间
- 建立工单状态流转表 `order_status_log`：关联工单 ID、原状态、新状态、操作人、操作时间、备注，用于报修进度时间轴展示
- 建立维修员技能与区域表 `worker_skill`：维修员 ID、负责小区 ID、技能标签，供智能派单匹配使用

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | repair_record、order_status_log、worker_skill |
| SQL 脚本 | backend/sql/elevator_init.sql 第 4 章第 7—8 节 |

### 模块四业务表建表
- 建立维保计划表 `maintain_plan`：计划名称、电梯 ID、维保类型、周期天数、生效日期、下次维保日期、负责人、计划状态
- 建立维保检查项模板表 `maintain_item`：模板名称、适用电梯类型、检查项名称、排序号，检查项含曳引机、安全装置等
- 建立巡检记录表 `inspection_record`：关联计划 ID、电梯 ID、巡检工单编号、执行人、打卡时间、打卡位置、执行结果、异常说明
- 建立巡检检查项结果表 `inspection_item_result`：关联巡检记录 ID、检查项 ID、检查项名称、是否正常、备注
- 建立维保档案表 `maintain_archive`：电梯 ID、归档类型、归档时间、记录摘要、关联巡检记录 ID

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | maintain_plan、maintain_item、inspection_record、inspection_item_result、maintain_archive |
| SQL 脚本 | backend/sql/elevator_init.sql 第 4 章第 10—14 节 |

### 模块五业务表建表
- 建立预警规则表 `warning_rule`：规则名称、规则类型（工单超期或维保临期）、阈值、阈值单位、通知对象角色、是否启用
- 建立预警信息表 `warning_info`：预警类型、关联业务 ID、预警内容、接收人 ID、是否已读、生成时间
- 建立电梯健康评分表 `elevator_health`：电梯 ID、统计周期、故障率、维保完成率、巡检合格率、健康评分、健康等级、生成时间

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | warning_rule、warning_info、elevator_health |
| SQL 脚本 | backend/sql/elevator_init.sql 第 4 章第 15—17 节 |

### sys_user 扩展与定时任务注册
- `sys_user` 内置 `community_id` 字段，对应论文表3-1「所属小区ID」，供数据权限按小区隔离
- `sys_user` 的 `phonenumber` 加唯一索引 `uk_user_phonenumber`，供手机号密码登录定位账号
- 注册三个业务定时任务到 `sys_job`：巡检工单自动生成、超期预警扫描、电梯健康评分重算
- 三个任务此前只写了 Task 类，未注册，导致只能手工触发，本步骤补上注册

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | sys_user、sys_job |
| SQL 脚本 | backend/sql/elevator_init.sql 第 2 章（sys_user）、第 5 章第六节（定时任务） |

### 菜单与权限初始化数据
- 插入 5 条一级目录菜单，`menu_type='M'`，对应五个功能模块
- 插入 17 条二级菜单，`menu_type='C'`，菜单名称与论文子功能名称一致，`component` 字段指向 `admin-web/src/views/` 下的实际页面路径
- 插入按钮权限行，`menu_type='F'`，权限串按 `plan.md` 第 5.2 节三段式命名
- 建立四个角色：业主、物业、维修员、管理员，并配置 `sys_role_menu` 关联

**交付物**

| 类型 | 清单 |
| --- | --- |
| 数据表 | sys_menu、sys_role、sys_role_menu、sys_user_role |
| SQL 脚本 | backend/sql/elevator_init.sql 第 5 章第一节、第二节 |

### 基础数据与测试数据初始化
- 插入演示小区、楼栋、电梯数据，电梯数量覆盖多个楼栋
- 插入四类角色的演示账号，账号关联所属小区
- 插入维保检查项模板数据
- 插入预警规则数据
